# Registro de Decisões Técnicas (`DECISIONS.md`)

| Data | Decisão | Justificativa e Impacto |
|---|---|---|
| 2026-11-20 | **Isolamento de dados internos em `store_internal_records`** | No PostgREST/Supabase, políticas RLS em `stores` filtram linhas, não colunas. Separar `contact_name`, `contact_email`, `contact_phone`, `internal_notes`, `subscription_internal_notes` e erros de convite em `store_internal_records` (com RLS exclusiva de `platform_admins`) impede vazamento de dados comerciais internos para proprietários ou editores via consulta direta à tabela `stores`. |
| 2026-11-20 | **Suporte a `VITE_SUPABASE_PUBLISHABLE_KEY` com fallback para `VITE_SUPABASE_ANON_KEY`** | O Supabase está migrando chaves públicas para o formato `sb_publishable_...`. O cliente frontend aceita o padrão atual (`VITE_SUPABASE_PUBLISHABLE_KEY`) e mantém compatibilidade com `VITE_SUPABASE_ANON_KEY`. O plugin `validateEnvOnBuild` em `vite.config.ts` bloqueia qualquer variável `VITE_*` contendo `SERVICE_ROLE`, `SECRET` ou `sb_secret_`. |
| 2026-11-20 | **Separação entre `get_public_menu(p_slug)` e `get_public_menu_at(p_slug, p_at)`** | A RPC pública exposta a `anon` chama exclusivamente `now()` do banco (`get_public_menu`). A função interna `get_public_menu_at` permanece revogada de `PUBLIC`/`anon`/`authenticated` e permite validar limites temporais exatos de promoções pontuais, semanais e `grace_until` nos testes PostgreSQL sem alterar o relógio do servidor. |
| 2026-11-20 | **Validação compartilhada pura nas Edge Functions (`_shared/validation.ts`)** | Permitiu reutilizar exatamente o mesmo validador de payloads de `provision-store` e `resend-store-invite` nos testes unitários Node/Vitest sem duplicar regras nem depender de importações Deno-específicas nos testes frontend. |
| 2026-11-20 | **Tailwind CSS v4 com `@tailwindcss/vite` + React 19 + Zod v4 + `@hookform/resolvers` v5** | Stack atualizada conforme versões estáveis vigentes, eliminando `tailwind.config.js` legado e garantindo compatibilidade tipada entre `zod@4` e `react-hook-form`. |
| 2026-11-20 | **Harness efêmero local de testes PostgreSQL 16 (`scripts/test-db.sh`)** | Como o ambiente local possui PostgreSQL 16 sem Docker/Supabase CLI, foi criado um harness efêmero com Unix socket local que inicializa shims compatíveis de `auth` e `storage`, aplica todas as migrations `0001..0006` e executa a suíte de asserções RLS/regras de negócio reais. |
| 2026-11-20 | **`wrangler.jsonc` para SPA no Cloudflare Workers Static Assets / Pages** | A interface atual da Cloudflare provisiona projetos Git como Workers com Static Assets (`npx wrangler deploy`), onde `public/_redirects` com `/* /index.html 200` gera erro de loop `10021` e a ausência de `wrangler.jsonc` faz o Wrangler detectar o app incorretamente como Hydrogen. Adotado `wrangler.jsonc` com `not_found_handling: "single-page-application"` apontando para `./dist`, mantendo compatibilidade nativa com SPA tanto em Workers quanto no Pages (que ativa SPA automaticamente sem `404.html`). |
